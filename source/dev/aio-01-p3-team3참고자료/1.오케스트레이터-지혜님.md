오케스트레이터는 **"에이전트들을 순서대로 부르고, 결과를 보고 다음 길을 정하는 사람"**이에요. 직접 날씨를 조회하거나 문장을 쓰지는 않습니다.

## 1. 해야 할 일 / 하지 말아야 할 일

가이드가 역할마다 이걸 정의하라고 하니 설계서에 그대로 쓰면 됩니다.

| 해야 할 일 | 하지 말아야 할 일 |
|---|---|
| 에이전트 호출 순서와 병렬 실행 관리 | API를 직접 호출 (MCP 도구 담당) |
| Validation 결과(PASS/RETRY/FAIL)에 따라 경로 결정 | 위험도 직접 판정 (Writer 담당) |
| Join Guard, Handoff Guard 판단 | 재시도·캐시 로직 직접 구현 (AutoHealing 담당) |
| task_id 발급, 시도 횟수 관리 | 지병 등 민감정보를 다음 단계로 전달 |
| 최종 성공·실패·종료 판단 | |

## 2. 구현할 것

**① FastAPI 엔드포인트**
- `POST /alert`: 프로필과 장애 주입 옵션을 받아 전체 흐름 실행
- `GET /health`, `GET /logs`: 상태 확인, 실행 기록 조회

**② 흐름 코드 (뼈대)**
```python
async def run_alert(profile, fault=None):
    task_id = new_task_id()

    # Orchestration 1: 병렬 조사
    weather, shelter, prof = await asyncio.gather(
        weather_agent(profile, fault),
        shelter_agent(profile, fault),
        profile_agent(profile),
        return_exceptions=True,
    )

    # Validation + Join Guard
    if not join_guard(weather, shelter, prof):
        return safe_fail(task_id)        # 안전 종료 + 기본 안내

    research = aggregate(task_id, weather, shelter, prof)

    # Handoff Guard
    if not needs_alert(research):
        return no_alert(task_id)          # 위험 없음, 종료

    # Orchestration 2
    alert = await writer_agent(research)
    result = await summary_agent(alert)
    return result
```

**③ Guard 규칙 3개 (코드 규칙으로, LLM 아님)**
- **Join Guard**: Weather 실패 → 안전 종료 / Shelter 실패 → "쉼터 정보 없음"으로 진행 / Profile 누락 → 취약도 "상"으로 진행
- **Handoff Guard**: 특보 없음 + 체감온도 정상 + 취약도 하 → 알림 없이 종료
- **최대 반복**: RETRY는 최대 3회, 넘으면 FAIL

**④ Handoff 데이터 형식 정의**
SafetyResearchResult에 아래 필드를 넣고 팀 전체에 공유합니다.
```json
{
  "task_id": "task-102",
  "attempt": 1,
  "weather": {...},
  "shelters": [...],
  "vulnerability": "상",
  "errors": ["weather: timeout → cache 사용"]
}
```
`vulnerability`만 넘기고 지병 원문은 넘기지 않는 게 포인트예요.

## 3. 팀원과의 연결

| 누구와 | 무엇을 맞추나 |
|---|---|
| 데이터·MCP | 도구 입력·출력 형식 |
| AutoHealing | 도구가 실패를 어떻게 알려주는지 (예외 vs `{"status": "fallback"}`) |
| LLM 에이전트 | Writer, Summary의 입력·출력 JSON |
| 프런트 | `/alert` 요청·응답 형식, 장애 주입 옵션 이름 |

특히 **AutoHealing 담당과의 약속**이 중요해요. 도구가 캐시로 복구했으면 성공으로 볼지, 결과에 "캐시 사용" 표시를 남길지를 정해야 Guard가 제대로 판단합니다.
