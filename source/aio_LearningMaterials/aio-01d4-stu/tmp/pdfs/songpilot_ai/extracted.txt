SongPilot AI
기관·기업용 AI 음악 콘텐츠 기획 및 제작 워크플로우
설계 단계  |  아래 기능은 MVP 구현 목표이며 구현·검증 완료를 의미하지 않음
01
문제와 목적
공공기관·기업·교육기관은 음악 제작의 목적·대상·필수 문구를 반복 전달하고 수작업으로 검수한다. 요구사항과 검수
결과를 표준화해 누락과 수정 반복을 줄이는 것이 목표다.
가상 업무 사례
특정 기관의 실제 도입 사례가 아닙니다
사용자  지자체 시민안전 홍보팀
“여름철 폭염 예방 캠페인용 30초 홍보 음악을 기획해 주세요. 어르신도 이해하기 쉬운 밝고 신뢰감 있는 
분위기, 쉬운 한국어를 사용해 주세요.”
필수 메시지  물 마시기 · 그늘 이용 · 낮 시간 야외활동 자제
02
AI 처리와 실패 분기
1  기획
목적·대상·채널·필수 조건 구조화
2  가사
쉬운 한국어, 짧은 후렴·반복구 작성
3  스타일
장르·템포·보컬·악기를 Style Prompt로 변환
4  검수
코드로 문구·형식, AI로 의미·명확성 점검
5  분기
최대 2회 수정, 상충·불확실·초과 시 확인
6  승인
담당자가 해당 버전의 제작 패키지를 검토
03
결과물과 차별점
가사 초안
Suno Style Prompt
검수 체크리스트
JSON·Markdown / 수정 이력
역할별 데이터 계약과 상태 추적
필수 문구의 정확 일치·의미 검수
실패 원인·재시도·승인 버전 기록
04
최소 기술 구성
Python · LangGraph · Pydantic · Streamlit · LLM API 1종 · JSON 저장 · pytest
동일 LLM에 역할별 계약 적용. RAG는 기관 문서 검색 필요 시, Docker는 핵심 기능 확인 후 도입.
05
MVP 구현 범위
포함 단일 캠페인·트랙의 입력, 분리 생성, 검수·수정·승인, 저장·불러오기와 실행 이력
제외 실제 음원 생성·마스터링, 자동 게시, 기관 내부 시스템 연동. 여러 트랙은 후속 확장.
06
완료 기준
① 가사·Style Prompt 분리 패키지 생성 ② 누락·형식 오류 탐지 및 수정·사용자 확인 분기
③ JSON·Markdown 저장·불러오기, 단계별 상태·검수·이력 확인 ④ 정상·실패·재시도·승인 테스트
목표 30초 / 실제 음원 길이 미검증. 패키지 승인 후 외부 도구에서 활용하며, 최종 음원·게시·방송은 별도 승인.
