[LLM 에이전트 계획서 수정 공유 - 해든]

한파 상황까지 점검하면서 LLM 파트 계획서를 일부 고쳤어요. 다른 파트와 맞물리는 부분이 있어서, 확정하기 전에 의견 부탁드려요. (수정본: notes/multi_agent_safety_service_plan_v2.md)

■ 바뀐 점과 이유
1. 체감온도 공식에 적용 조건 추가 (기온 10℃ 이하, 풍속 1.3m/s 이상일 때만)
   → 조건이 없으면 바람 없는 -12℃가 체감 +5.7℃로 계산돼 한파 알림이 안 나가요.
2. 날씨 단계(normal/advisory/severe)를 RiskAgent에서 직접 계산
   → 지금은 계산하는 곳이 정해져 있지 않아요. 한파 판정에는 전날 최저기온과 2일 지속 여부가 필요해요.
3. 냉방·난방을 has_cooling / has_heating 두 칸으로 분리
   → 한 칸이면 에어컨만 있고 난방이 부족한 분이 겨울에 덜 취약하게 나와요.
4. LLM 실패 시 대체 문구를 여름용/겨울용으로 분리
   → 기존 문구의 "물을 자주 드세요"가 한파 날에도 나가요.
5. 응답에 hazard(heat/cold) 추가
   → 화면과 보호자 문구에 무엇 때문에 위험한지 보여주려고요.
6. 한파 테스트 기대값을 하나로 고정 (예: 최저 -12℃ 2일 + 취약도 중 → 경고)
   → 기존에는 "위험 또는 경고"라서 테스트가 통과/실패를 판단할 수 없었어요.

■ 파트별로 확인 부탁드려요
[지혜 님 · 오케스트레이터]
- Handoff Guard를 Writer 앞(위험도 계산 직후)에 두고, 기준을 "위험도가 관심이면 종료" 하나로 바꿔도 될까요? 지금 기준(특보 없음 + 체감 정상 + 취약도 하)과 결과가 조금 달라요.
- 위험도 '주의'도 알림 발송(alert)으로 처리해도 될까요?

[상옥 님 · AutoHealing]
- LLM 형식 오류 시 재요청 1회는 AutoHealing 쪽 with_healing에서 감싸고, 저는 검증 함수·필수 키·계절별 대체 문구를 넘기는 걸로 맞을까요?
- 응답에 fallback_used(true/false)를 추가해도 될까요?

[두나 님 · 데이터·MCP]
- get_weather 출력에 min_temp_yesterday, min_temp_tomorrow를 추가할 수 있을까요? (한파 특보 기준에 필요해요)
- 체감온도 함수에 위 1번 조건을 넣어 주실 수 있을까요?
- base는 "예보 발표 시각" 뜻으로만 쓰고, 제 쪽 판정 문구는 stage_label로 이름을 바꿨어요. 괜찮을까요?

[수언 님 · 프런트]
- 위험도·취약도 값은 지금처럼 한글(관심/주의/경고/위험, 상/중/하)로 유지할게요. 맞죠?
- 응답의 hazard 값으로 폭염/한파 표시를 넣을 수 있을까요?
- 계절 선택에 "봄·가을"을 추가할 수 있을까요? 시연 장면 2번(가을 → 알림 없음)을 고를 수 있게요.

다른 의견 있으면 편하게 말씀해 주세요. 정리되면 수정본에 반영할게요!
