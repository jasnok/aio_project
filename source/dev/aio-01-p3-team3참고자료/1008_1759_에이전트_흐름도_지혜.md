# 에이전트 흐름도

```text
시연 시나리오 선택
(normal / heat / induction / fall / critical)
          │
          ▼
[Orchestration 1: Care Monitoring]
          │
     ┌────┼─────┐
     ▼    ▼     ▼
 Vital   IoT   Profile
 Agent  Agent   Agent
     └────┼─────┘
          ▼
  출력 계약 Validation
  (구조 · 필수값 · 타입 · 범위)
          │
          ├─ 유효 ───────────────────────┐
          │                              │
          └─ 무효 / 호출 실패             │
                 ▼                       │
       Orchestrator 재시도 정책            │
       (횟수 · 타임아웃 · 재시도 여부)       │
          ├─ 재시도 → 해당 Agent 재호출     │
          └─ 한도 초과 → 캐시 폴백 또는 실패 │
                                         ▼
                                    Join Guard
                          (필수 결과·누락·폴백 상태 확인)
                                         │
                                    Aggregator
                                         │
                                  CareStatusResult
                                         │
                                   Handoff Guard
                             ┌───────────┴───────────┐
                             │ 정상                  │ 이상·대응 필요
                             ▼                       ▼
                            END        [Orchestration 2]
                                                   │
                                                   ▼
                                            Emergency Agent
                                      코드 규칙으로 위험도·조치 결정
                                      LLM은 설명 문장 생성
                                                   │
                                                   ▼
                                       LLM 출력 계약·안전 검사
                                       (스키마 및 문장 제약)
                                         ├─ 통과 → 다음 단계
                                         └─ 실패 → 재요청 / 템플릿
                                                   │
                                                   ▼
                                             Approval Gate
                                      ┌────────────┴───────────┐
                                      승인                      거절
                                       ▼                         ▼
                                  Action 실행                조치 없이 기록
                             (기기·알림·119, mock)
                                      └────────────┬────────────┘
                                                   ▼
                                             Summary Agent
                                      LLM 문장 생성 및 검사
                                      실패 시 재요청 / 템플릿
                                                   │
                                                   ▼
                                            결과 저장·표시
                                                   │
                                                  END
```

## 참고

- `critical`은 시연 시나리오 입력이며 별도의 Critic 단계가 아닙니다.
- 현재 프로젝트에는 별도의 Critic Agent 단계가 없습니다.
- Validation은 Agent 출력 계약(구조·필수값·타입·범위)을 확인합니다. 재시도 여부와 횟수는 Orchestrator/AutoHealing 정책이 결정합니다.
- 캐시 폴백은 조회 데이터처럼 캐시 사용이 허용된 단계에 적용합니다. 기기 제어, 알림, 119 실행 결과는 캐시로 대체하지 않습니다.
- 이 도식은 일반적인 처리 구조를 요약한 것입니다. 재시도 횟수와 타임아웃은 단계별 코드 설정을 기준으로 관리합니다.
