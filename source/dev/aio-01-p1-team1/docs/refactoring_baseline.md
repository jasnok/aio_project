## 테스트는 무엇을 확인했나요?

| 영역 | 실행한 테스트 수 | 결과 |
|---|---:|---|
| 백엔드 | 172 | 전부 통과 |
| 관리자 화면 관련 로직 | 331 | 전부 통과 |
| 사용자 화면 관련 로직 | 156 | 전부 통과 |
| 합계 | **659** | **실패·오류 없음** |

세 앱의 기존 가상환경에서 `tests` 폴더를 각각 unittest로 실행했습니다. 테스트 도구 내부의 로컬 통신은 허용하고 외부 TCP 연결은 차단했습니다. 테스트에서 발생한 외부 서비스 변경은 없습니다.

백엔드 오류 처리 테스트 일부가 로그를 저장하려고 외부 연결을 시도했고, 19번의 연결 시도를 차단했습니다. 해당 테스트들은 모두 통과했습니다. 이는 테스트 중 외부 로그 저장 의존성이 남아 있다는 기준선 관찰이며, 실제 Supabase가 정상이라는 증거가 아닙니다. 향후 테스트에서는 로그 저장도 명확하게 분리합니다.

또한 백엔드 테스트 클라이언트의 `StarletteDeprecationWarning`을 확인했습니다. 지금 실패하는 오류는 아니며, 의존성을 정리할 때 호환성을 함께 점검할 항목입니다.

이번 결과는 기존 테스트가 확인하는 규칙이 유지된다는 의미입니다. 보안 문제의 해결, 실제 Gemini 응답, Redis 연결, Supabase 데이터 상태, 브라우저의 전체 사용 흐름은 검증 범위에 포함하지 않습니다.

상세 숫자와 실제 설치된 패키지 버전은 [기계 판독용 기준선 기록](baselines/2026-09-23.json)에 저장했습니다.

## 실행 환경에서 발견한 다음 단계의 과제

1. **설치 목록과 실제 환경의 차이:** BE requirements에는 `google-genai`와 `redis`가 있지만 현재 BE 가상환경에는 설치되어 있지 않습니다. 실제 AI·대화 저장 기능까지 실행하려면 다음 단계에서 설치 절차를 맞춰야 합니다.
2. **버전 차이:** 사용자 Streamlit은 1.41.1, 관리자 Streamlit은 1.52.2입니다. BE의 httpx는 0.27.2, 두 FE는 0.28.1입니다. 현재 기준으로 기록하고 이 단계에서는 변경하지 않았습니다.
3. **주소 설정 차이:** 관리자 API 주소는 Streamlit secrets에서 읽지만, 사용자 앱은 `.env`와 환경변수도 확인합니다. 설정 통일이 필요합니다.
4. **샘플 상담의 Redis 의존:** 상담 mock 모드도 Redis에서 기존 대화를 읽습니다. AI 키가 없는 것과 외부 저장소 없이 실행되는 것은 다릅니다.
5. **포트 충돌 가능성:** 기존 README의 두 Streamlit 실행 명령은 모두 기본 포트 8501을 사용합니다. 동시 실행 안내에서는 포트를 명시해야 합니다.
6. **공개 전 권한 보완:** 관리자·프로필·즐겨찾기 API 권한 문제는 아직 그대로입니다. 이 기록의 테스트 통과가 공개 배포 가능 판정을 의미하지 않습니다.

두 화면을 동시에 실행할 때 사용할 포트는 다음처럼 구분할 수 있습니다. 이는 다음 실행 안내를 위한 명시적 선택이며, 이번 단계에서 앱을 실행하거나 고정 설정으로 적용한 것은 아닙니다.

| 작업 폴더 | 해당 가상환경에서 실행할 명령 | 포트 |
|---|---|---:|
| `BE` | `python -m uvicorn app.main:app --reload --port 8000` | 8000 |
| `FE_User` | `python -m streamlit run app.py --server.port 8501` | 8501 |
| `FE_Admin` | `python -m streamlit run app.py --server.port 8502` | 8502 |

## 팀 결과물과 개인 기여는 어떻게 구분하나요?

[최종 회고](https://laycoder.tistory.com/252)에서 설명한 본인 기여는 공고 데이터 구조, 관리자 등록·관리, 사용자 공고 조회, 다중 이미지 처리, 문서 기반 자동 등록을 중심으로 기록합니다. 회원·상담·지도·로그 등 전체 기능을 개인 단독 개발로 표기하지 않습니다.

기존 `docs/plan.md`의 ‘실시간 로그 시각화 개인 담당’ 표현은 이 사용자의 기여를 판정하는 근거로 그대로 사용하지 않습니다. 이후 개인 리팩토링은 이번 기준점 이후의 변경으로 따로 설명합니다.

이번에 수행한 것은 기준점 보존, 브랜치 준비, 파일 동일성 확인, 테스트 재실행과 결과 기록입니다. 새로운 기능 구현은 아직 하지 않았습니다.

## 원본을 다시 확인하려면?

코드를 비교하려면 `portfolio-baseline-2026-09-23` 태그를 기준으로 Git 변경 내용을 확인하면 됩니다. 현재 작업 내용을 덮어쓰는 초기화 명령은 필요하지 않습니다.

원본 코드를 별도 폴더에서 보고 싶을 때는 저장소 루트에서 다음처럼 **아직 없는 새 경로**에 체크아웃할 수 있습니다.

```powershell
git worktree add --detach C:/dev/aio-01-p1-team1-baseline-2026-09-23 portfolio-baseline-2026-09-23
```

위 명령은 복구가 필요할 때의 안내이며 이번에는 실행하지 않았습니다. 새 폴더에는 당시 커밋의 코드만 들어갑니다. 미커밋 문서 3개는 로컬 보존 경로에서 별도로 확인하고, 실제 `.env`와 가상환경은 포함되지 않는다는 점을 구분합니다. `source.zip`도 새 폴더에 풀어 원본을 확인하는 데 사용할 수 있습니다.
