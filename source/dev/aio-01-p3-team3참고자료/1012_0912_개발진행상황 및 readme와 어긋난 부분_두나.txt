프로젝트 상태
구조는 README와 같습니다. frontend(Streamlit), backend(FastAPI), mcp_server(FastMCP) 세 개이고 루트 compose.yml로 함께 띄웁니다. MCP 도구는 9개로 README와 일치합니다. 시나리오 5개, 장애 이름 4개(vital/iot/vision/llm), /care/run·/care/approve 형식과 CareStatus 값도 맞습니다.
테스트는 backend 431개, mcp_server 125개, frontend 20개가 모두 통과했습니다. pytest 기본 임시폴더에 권한 오류가 나서 --basetemp를 따로 지정해 돌렸습니다. 저장소 문제는 아닙니다.

README와 어긋나는 곳
119 자동 연결 (가장 큰 차이)
README(1·3·5·6·9·14장)와 docs/scenarios.md는 critical에서 승인 없이 119에 바로 연결한다고 합니다.
실제 [risk.py:114-119](backend/src/rules/risk.py:114)는 ENABLE_AUTO_119 = False, ENABLE_AUTO_119_VITAL = False입니다. 그래서 critical도 승인 요청으로 갑니다. [test_care_run.py:131](backend/tests/test_care_run.py:131)의 test_critical_119_is_approval_request_not_auto가 이 동작을 확인합니다.
자동 연결 쪽 테스트는 flag를 True로 바꿔야만 통과합니다. 시연 시나리오 5번과 8번이 README대로 동작하지 않는다는 뜻입니다.
코드 주석에는 "해든 결정으로 끔"이라고 적혀 있어서, 문서와 코드 중 어느 쪽이 최종인지 팀이 정해야 합니다.

승인 대기 60초 후 자동 119 (README에 없음)
승인 요청에 60초 동안 응답이 없으면 119에 자동 연결됩니다(on_timeout: execute). 응답의 decided_by에도 "timeout"이 있습니다.
README는 guardian과 auto만 적었고 "119 예외는 VITAL_SEVERE 하나뿐"이라고 합니다. 그 원칙이 이 동작과 충돌합니다.
CCTV 이미지가 안 나오는 버그
[api_client.py:142](frontend/src/api_client.py:142)는 backend의 /cctv/{name}을 호출합니다.
이 경로는 MCP 서버([server.py:84](mcp_server/src/server.py:84))에만 있고 backend [main.py](backend/src/main.py)에는 없습니다. 지금 상태로는 승인 화면의 캡처가 404로 실패할 것으로 보입니다. 직접 띄워서 확인한 것은 아니고 코드만 보고 판단했습니다.
README 2장 구성도의 호출 경로에도 이 연결이 없습니다.

API 명세 (11장)
GET /logs는 README에 있지만 코드에 없습니다.
코드에 있는데 README에 없는 것: GET /health/ready, POST /vitals/readings, backend /cctv/*(위 3번).

바이탈 15초 수집 기능이 README에 없음
mcp_server/src/vital_sender.py가 15초마다 backend로 전송합니다. 이를 위한 vital_readings와 profiles 테이블도 있습니다.
README 7장의 SQL에는 cache와 run_logs만 있습니다. 그 SQL도 코드와 달라서, saved_at은 REAL이고 status 값은 success/retry/fallback/fail/error입니다. README에 있는 approved/rejected는 없습니다.
관련 메모는 docs/README 바이탈 15초…수정안.md에 있는데 본 README에 반영되지 않았습니다.

사소한 불일치
이미지 파일: README는 4개를 준비한다고 하는데 실제로는 12개이고 .png도 섞여 있습니다.
MCP 도구 인자: README는 get_vitals(person_id), get_indoor_env(home_id)라고 하지만 실제는 (profile_id, scenario)입니다.
compose.yml의 프로젝트 이름이 heat-cold-alert로 다른 프로젝트 이름입니다.
.env.example에 KMA_API_KEY, GEOCODING_API_URL, FORECAST_API_URL이 있는데 README에 설명이 없습니다.
14장 시험 기록표와 지표는 비어 있고, 맨 아래 실행 정보(배포 URL 등)도 비어 있습니다.
docs/에 README 초안이 5개쯤 있고 notes/에는 실험 스크립트가 있습니다. 제출 전에 정리하는 게 좋겠습니다.
