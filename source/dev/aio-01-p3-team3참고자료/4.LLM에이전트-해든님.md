LLM 에이전트 담당은 **"판단 결과를 사람이 읽을 문장으로 바꾸는 사람"**이에요. 이틀 범위에서는 판정은 코드 규칙으로, 문장은 LLM으로 나누는 게 안정적입니다.

## 1. 해야 할 일 / 하지 말아야 할 일

| 해야 할 일 | 하지 말아야 할 일 |
|---|---|
| 취약도 계산 함수 (Profile, 코드) | 위험도를 LLM이 마음대로 정하기 |
| 위험도 규칙표 (Writer, 코드) | 질병 진단, 약 복용 조언 |
| 행동요령·안내 문장 생성 (LLM) | 입력에 없는 쉼터·수치 지어내기 |
| 출력 필수 키 목록과 템플릿 문구 제공 | 재시도 로직 구현 (AutoHealing) |

**"LLM은 판단하지 않고 전달만 한다"**가 이 역할의 원칙이에요. 발표 때 "왜 판정을 코드로 했나?"라는 질문에 "안전 서비스라 판단은 일관되고 검증 가능해야 해서"라고 답할 수 있습니다.

## 2. Profile: 취약도 계산 (코드)

```python
def vulnerability(p):
    score = 0
    if p.get("age", 80) >= 75: score += 1
    if p.get("lives_alone", True): score += 1
    if p.get("has_condition", True): score += 1   # 지병 유무만 사용
    if not p.get("has_cooling_heating", False): score += 1
    return "상" if score >= 3 else "중" if score >= 2 else "하"
```
값이 없으면 위험한 쪽으로 기본값을 잡아서, 정보가 빠져도 보수적으로 판단하게 했어요. 지병명은 쓰지 않고 유무만 봅니다.

## 3. Writer: 위험도 판정 (코드) + 행동요령 (LLM)

**규칙표 예시** (기준 온도는 기상청 특보 기준을 확인해서 조정하세요)

| 날씨 | 취약도 하 | 중 | 상 |
|---|---|---|---|
| 정상 | 관심 | 관심 | 주의 |
| 더위/추위 주의 수준 | 주의 | 경고 | 경고 |
| 심한 더위/추위 | 경고 | 위험 | 위험 |

**프롬프트**
```
너는 어르신 안전 안내문을 쓰는 도우미다.
아래 정보만 사용해서 행동요령 3가지를 만든다.

[정보]
계절: {season} / 위험도: {risk_level}
최고기온: {max_temp} / 최저기온: {min_temp}
추천 쉼터: {shelter_name} ({distance_m}m, {open})

[규칙]
- 각 항목은 20자 이내, 어르신이 바로 할 수 있는 행동
- 정보에 없는 장소나 수치는 쓰지 않는다
- 질병이나 약에 대한 조언은 하지 않는다
- 아래 JSON 형식으로만 답한다

{"actions": ["...", "...", "..."], "reason": "판정 근거 한 문장"}
```

## 4. Summary: 어르신용 / 보호자용 (LLM)

```
아래 안전 정보를 두 사람에게 맞게 다시 쓴다.

[정보]
위험도: {risk_level} / 행동요령: {actions}
추천 쉼터: {shelter_name} ({distance_m}m) / 날씨 기준: {base}

[어르신용 규칙]
- 90자 이내, 존댓말, 쉬운 말
- 숫자는 최소화, 가장 중요한 행동 하나만 강조

[보호자용 규칙]
- 위험도, 이유, 추천 쉼터를 포함
- 위험도가 경고 이상이면 안부 전화를 권한다

JSON 형식으로만 답한다:
{"elder_message": "...", "guardian_message": "..."}
```

## 5. AutoHealing 담당에게 넘길 것

**필수 키**
- Writer: `actions`(3개 리스트), `reason`
- Summary: `elder_message`, `guardian_message`

**템플릿 문구** (LLM 실패 시)
```python
FALLBACK = {
  "actions": ["물 자주 마시기", "한낮·새벽 외출 줄이기", "가까운 쉼터 이용하기"],
  "elder_message": "오늘 날씨가 위험해요. 무리하지 마시고 가까운 쉼터에서 쉬세요.",
  "guardian_message": "위험도 {risk_level}. 어르신께 안부 전화를 드려 주세요. 추천 쉼터: {shelter_name}"
}
```
템플릿도 위험도와 쉼터 이름은 채워 넣어서, 장애 상황에서도 최소한의 정보가 전달되게 하세요.

## 6. 테스트

실제 API를 기다리지 말고 고정 입력 3개로 먼저 돌리세요.
- 한여름, 35℃, 취약도 상 → 위험
- 한겨울, -12℃, 취약도 중 → 위험 또는 경고
- 가을, 18℃, 취약도 하 → 관심 (Handoff Guard에서 걸러져야 함)

각각 5번씩 돌려서 JSON이 깨지지 않는지, 지어낸 장소가 없는지, 어르신용이 90자를 넘지 않는지 확인하면 됩니다.

## 7. 일정

| 시점 | 할 일 |
|---|---|
| 오늘 저녁 | 취약도 함수, 규칙표 코드, 두 프롬프트를 고정 입력으로 테스트 |
| 내일 오전 | 필수 키·템플릿을 AutoHealing에 전달, 실제 흐름에 연결 |
| 내일 오후 | 문장 다듬기, 시연용 결과 화면 확인 |

모델 설정에서 temperature를 낮게(0~0.3) 두면 형식이 훨씬 안정적이에요. JSON 출력 모드를 지원하는 모델이면 켜두세요.
