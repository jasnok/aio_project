# 팀 합의 항목: 해든 쪽 제안값 (10/8)

지혜 님 표의 순서를 그대로 따랐어요. 제안값 대부분은 해든 코드에 이미 맞춰 둔 형태예요. `humidity`, `measured_at`, `errors` 모양, `person`·`fault`는 해든 코드가 쓰지 않는 부분이라 담당자 안을 따라도 괜찮아요.

## 합의 진행 방법 (추천)

1. **17:00 점검 전에** 이 표를 팀 채팅에 올리고, 담당자가 각 줄에 "OK" 또는 "수정: ..."만 답해요. 빈칸부터 토론하면 길어지니, 제안값을 먼저 깔고 반대 의견만 받는 방식이에요.
2. **17:00 점검 때** "수정"이 달린 줄만 15분 안에 정해요. 이때 나머지는 OK로 확정해요.
3. 확정된 값은 **지혜 님이 README 계약 절에 한 번에 반영**해요. 문서가 하나여야 각자 코드가 어긋나지 않아요.
4. 확정 뒤 바꾸려면 팀 채팅에 먼저 알리고 README를 같이 고쳐요.

## 항목별 제안값

| 항목 | 해든 쪽 제안값 | 확인할 사람 |
|---|---|---|
| CareStatusResult | 필수: `task_id`, `vitals`, `env`, `devices`, `vulnerability`. 선택: `attempt`, `scenario`, `cctv`, `errors`, **`area`(병원 찾기용, 새로 추가)**, `fall_event`(스피커 응답). 값이 빠지면 해든 코드는 위험한 쪽으로 판단 | 두나·상옥 |
| vitals | `hr`(회/분), `sbp`(mmHg, 수축기만), `temp`(℃), `spo2`(%), `source`("live"/"cache"), `measured_at`(ISO 시각). 화면에는 "혈압 125"처럼 수축기만 보여도 충분 | 두나·수언 |
| env, devices | env: `temp`(℃), `humidity`(%, 판단에는 아직 안 씀). devices: `aircon`, `induction` 값은 `"on"`/`"off"` | 두나 |
| cctv | `image_path`, `available`, `person_visible`(true/false), `posture`(standing/sitting/lying/fallen/none), `fall_suspected`, `confidence`(high/low), `description`(한 문장). 분석 실패면 `available: false`와 `error` | 두나·수언 |
| vulnerability | `"상"`/`"중"`/`"하"` 문자열 하나만 넘김. 지병 이름 원문은 넘기지 않고 프로필에서 해든 함수가 계산 | 해든 |
| source, errors | 바이탈이 캐시면 `source: "cache"` → 해든 코드는 119 자동 연결을 안 함. `errors`는 `[{"step","error","attempt"}]` 목록, 최종 실패면 응답 `status: "fail"` | 상옥 |
| EmergencyResult | `risk_level`, `reason`, `reason_codes`, `actions`, `hospital`, `auto_119`. actions 한 개는 `{"type","label","text","needs_approval","timeout_seconds","on_timeout"}`. 119·기기 제어는 승인 필요, 스피커·병원 정보·보호자 알림은 승인 없음. 119 바로 연결은 `needs_approval: false, auto: true` | 두나 |
| POST /care/run | 요청: `person`(어르신 id), `scenario`, `fault`(선택, 상옥 장애 주입). 승인 대기 응답: `status: "pending_approval"`, `risk_level`, `reason`, `actions`, `current_step`. 119 바로 연결이면 대기 없이 `status: "done"`, `decided_by: "auto"` | 수언·두나 |
| POST /care/approve | 요청: `task_id`, `approved`(true/false). 응답: `status`, `executed`, `guardian_message`, `elder_message`, **`decided_by`(guardian/auto/timeout, 새로 추가)**. 60초 무응답은 서버 타이머가 같은 처리 함수를 `approved: null`로 부름 | 두나·수언 |
| 공통 상태값 | 5개 그대로(no_issue / pending_approval / done / rejected / fail). 새 값은 만들지 않고 `decided_by`로 구분. `current_step` 예: "위험 판정 → 보호자 승인 대기", "보호자 응답 없음(60초) → 119 자동 연결 → 안내 전송" | 전체 |

## 해든 코드와 다를 수 있어 꼭 확인할 것

- `area`, `decided_by` 두 키는 README에 없던 것이라 지혜 님 동의가 먼저 필요해요.
- 119 바로 연결(승인 없이)은 README 원칙 ①의 예외라서 기화 님 결정이 필요해요. 안 하면 해든 코드에서 `ENABLE_AUTO_119 = False` 한 줄만 바꾸면 돼요.
- 혈압을 수축기만 쓰는 건 NEWS2 기준을 따른 거예요. 두나 님 mock 데이터에 이완기가 있어도 무시하면 돼요.
