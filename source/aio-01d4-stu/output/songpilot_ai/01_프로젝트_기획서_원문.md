# SongPilot AI — 기관·기업용 AI 음악 콘텐츠 기획 및 제작 워크플로우

현재 단계: 프로젝트 설계 | 아래 내용은 MVP 구현 목표이며 구현·검증 완료를 의미하지 않음

## 문제와 목적
공공기관 홍보팀·기업 브랜드팀·교육기관은 음악 제작 시 목적·대상·필수 문구를 반복 전달하고 결과를 수작업으로 검수한다. SongPilot AI는 요구사항 누락과 수정 반복을 줄이도록 제작 조건과 검수 결과를 표준화한다.

## 가상 업무 사례
사용자: 지자체 시민안전 홍보팀

“여름철 폭염 예방 캠페인용 30초 홍보 음악을 기획해 주세요. 어르신도 이해하기 쉬운 밝고 신뢰감 있는 분위기와 쉬운 한국어를 사용해 주세요.”

필수 메시지: 물 마시기 / 그늘 이용 / 낮 시간 야외활동 자제

특정 기관의 실제 도입 사례가 아닌 프로젝트 설계용 가상 시나리오다.

## AI 처리 단계
1. 기획 에이전트: 목적·대상·채널·필수 조건을 구조화한다.
2. 가사 에이전트: 쉬운 한국어로 짧은 후렴과 반복 문구를 작성한다.
3. 스타일 에이전트: 장르·템포·보컬·악기를 Suno Style Prompt로 변환한다.
4. 검수: 코드로 문구·금지어·형식을, 검수 에이전트로 의미·명확성을 점검한다.
5. 실패 분기: 최대 2회 수정하고, 상충·불확실·상한 초과 시 사용자에게 확인한다.
6. 담당자 승인: 검수 결과와 해당 버전의 제작 패키지를 검토한다.

## 결과물과 차별점
가사 초안 / Suno Style Prompt / 검수 체크리스트 / JSON·Markdown 패키지와 수정 이력

역할별 에이전트와 데이터 계약을 분리한다. 필수 문구의 정확 일치와 필수 메시지의 의미 포함을 구별하고, 단계별 상태·실패 원인·재시도·승인 버전을 남긴다.

## 최소 기술 구성
Python · LangGraph · Pydantic · Streamlit · LLM API 1종 · JSON 저장 · pytest

RAG는 기관 문서 검색이 필요해질 때, Docker는 핵심 기능 확인 후 도입한다. 에이전트는 역할을 나누되 동일 LLM을 사용할 수 있다.

## MVP 구현 범위
포함: 단일 캠페인·트랙, 요구사항 입력, 가사·스타일 분리 생성, 검수·수정·승인, 저장·불러오기와 실행 이력.

제외: 실제 음원 생성·마스터링, 자동 게시, 기관 내부 시스템 연동. 여러 트랙·캠페인 시리즈는 후속 확장이다.

## 완료 기준
- 가사·Style Prompt가 분리된 제작 패키지가 생성된다.
- 누락·형식 오류를 탐지하고 수정 또는 사용자 확인으로 분기한다.
- JSON·Markdown 저장·불러오기와 단계별 상태·검수·이력 확인이 가능하다.
- 정상·누락·실패·재시도·승인 경로의 테스트를 통과한다.

목표 길이는 30초이며 실제 음원 길이는 미검증이다. 패키지 승인 후 외부 도구에서 활용하고, 최종 음원과 게시·방송은 별도 승인한다.
